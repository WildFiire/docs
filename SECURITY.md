# Security Policy

## Supported Versions

Only the latest release on the `main` branch is actively supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

The WildFire team takes the security of our platform, documentation, and users seriously. If you discover a security vulnerability or potential exposure within this repository or associated services, please report it responsibly.

### How to Report:
1. **GitHub Private Security Advisory (Recommended):**  
   Navigate to the **Security** tab of this repository on GitHub and select **"Report a vulnerability"**. This allows confidential triage directly with the maintainers.
2. **Direct Security Email:**  
   Send an encrypted email detailing your findings to: **`security@wildfire.ro`**.

### What to Include:
- A clear description of the vulnerability and its potential security impact.
- Step-by-step reproduction steps or a minimal Proof of Concept (PoC).
- Relevant browser/Node.js versions, affected endpoints, or file paths.

### What NOT to Do:
- **Do NOT open public GitHub issues, discussions, or pull requests** detailing an unpatched security vulnerability.
- **Do NOT disclose details publicly** on Discord or social media before the vulnerability has been triaged and resolved.
- **Do NOT attempt destructive actions** (e.g. data exfiltration, denial-of-service, modifying production database records, or accessing user accounts that do not belong to you).

---

## Response & Resolution SLA

- **Initial Triage:** Within **48 hours** of receiving your report.
- **Status Updates:** Regular updates on remediation progress every **3 to 5 business days**.
- **Fix Deployment:** Critical vulnerabilities are typically patched within **7 days**.
- **Public Disclosure:** Coordinated release and CVE assignment (if applicable) following deployment of the fix.

---

## Safe Harbor

Activities conducted in good faith under this policy, focused on discovering and reporting vulnerabilities without causing service disruption or compromising personal data, are considered authorized. We will not pursue legal action against researchers acting in compliance with these guidelines.
